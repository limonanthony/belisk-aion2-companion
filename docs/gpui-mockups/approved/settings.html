Behaviour carried over

  • Shortcuts: a duplicate combination is refused before it is saved; a combination another program holds is reported per shortcut and the previous one keeps working. Blank turns a shortcut off.
  • Personal bests: Reset asks for a second click; bests survive deleting history. Up to six were listed before; here the whole table scrolls.
  • Recording: the first two minutes on an unfamiliar server are recorded automatically (newest five kept, never leave the PC). Replay runs a recording through the live meter and needs the meter running.
  • Developer tuning stays out: snapshot interval, packet size threshold and the resync delays.
  • Reset settings (About › Storage): the build's dialog says what is reset and what is kept: "Settings go back to their defaults, including the Capture switches. Fight history, personal bests, recordings and boss corrections are kept."
  • About lists only what the repository grounds, as the build does: GPL-3.0-only (LICENSE), the fork chain Helveticxa/Aether then ZDYoung0519/NOIA2 (both GPL-3.0-only), Kuroukihime's data (GPL-3.0), the references, GPUI (Apache-2.0), Lucide (ISC), Barlow Semi Condensed (SIL OFL 1.1) and WinDivert. Npcap is a dependency the user installs; WinDivert is bundled, and no licence text for it is in the repository yet.

About › Updates (approved 2026-10-09)

  • Where: a group "Updates" right after the app's own group, so it shows without scrolling. The group title says what is contacted: "Asks GitHub for the latest release; nothing about you or your game is sent." The app checks at launch, then once an hour, never more often (GitHub's 60 requests an hour per address); there is no switch to turn the checks off, and no beta channel. The hourly check goes on while an update is available or ready, so a newer release replaces a staged one.
  • Up to date: "1.5.1 is the latest version. Checked at 21:02; checked again at launch and every hour." and "Check now". After any check, Check now is disabled for a minute ("Checked just now; you can check again in a minute.").
  • Available (automatic download off): "Release notes" (ghost, opens the GitHub release page in the browser; the app does not show the release body) and the primary "Update to 1.6.0". With automatic download on, the download starts at once.
  • Downloading / paused: the Slider's 4 px track as progress, "2.6 of 4.2 MB · at most 1 MB/s, paused while you fight"; always capped at 1 MB/s and paused while you fight, also after a click on Update. Cancel deletes the partial file (turning the switch off does too). Paused: the range dims.
  • Checking the download: its hash and its ed25519 signature (minisign-style; the public key is in the build); the build's spinner badge.
  • Ready: the primary "Restart to update"; the toolbar shows the same. Installing always waits for this click (or the toolbar's): the app closes and opens again in the new version.
  • Errors, never a pop-up during play: a failed check is a field message in bad under the row ("…did not pass its check (signature mismatch), so it was deleted. Nothing was installed.") with "Try again"; GitHub unreachable or limiting is a field message in warn with the next try's time; limited also disables Check now until GitHub's reset time (never a retry loop).
  • One bright button per view: "Update to 1.6.0" when available, "Restart to update" when ready; otherwise secondary or ghost.
  • Versions and times are invented: the version resets to 1.0.0; this build runs 1.5.1 and GitHub's latest is 1.6.0.

Reminders

  • Event reminders off: no card and no sound at any event time. Every row under it dims (label and description at 50%, control at 40%) and does not react, but keeps its value; turning reminders back on restores the same choices.
  • Remind me: 1, 2, 3 or 5 min before; 1 by default. One lead time for every event.
  • Sound: Windows' own Chimes sound (no bundled file), one per card, even when several events share it.
  • Show a test reminder: shows the card above the meter now, with the sound if it is on, whatever the event switches say. Because Settings may cover the meter, a good badge "Shown above the meter" appears beside the button and fades after 4 s.
  • Events: Shugo Festival, Dimensional Invasion and Rift portals are on by default; the others are listed, off.
  • Times follow this PC's clock. They are the European servers' times (Berlin), so a PC on another time zone would be off by its difference.

To-dos

  • Daily reset: a select with every hour, 00:00 to 23:00, 09:00 by default; the list opens scrolled to the chosen hour. The hour moves Today's countdown and the weekly reset with it, and the Resources window's daily refills (Shugo keys, Invasion keys, Nightmare) and the Daily Dungeon's weekly one; both windows follow at once. "Change" in the to-do window's footer opens this section.
  • Weekly reset: not a control. Wednesday, at the daily reset hour ("Wednesday 09:00", "Wednesday 17:00"): This week's to-dos start over and the Daily Dungeon gets its 14 tickets.
  • Membership: one switch for every character, off by default, in the group "Resources" (it was "Recharges"). It picks the membership cap of every ticket that has one, in the Resources window and the toolbar's counts: "Higher caps in the Resources window, on every character: Odyle Energy 840 instead of 560, Shugo keys 21 instead of 12." Off again, nothing is cut: a number above the cap is normal.
  • The game shows more: the game never says whether you have a membership, but a regular pool above the cap without it (18 Shugo keys with membership off) can only come from one. Then a quiet line under the description asks "Do you have a membership?", until the switch is on. No dialog, no automatic switch.
  • Restore default to-dos: on every character, every built-in to-do you hid comes back (Duty Commands too, which start hidden). Only to-dos are listed: the resources have no hide control any more, and a resource hidden before 2026-10-08 shows in the Resources window again without counting here. Your own to-dos, every count and every amount stay. The description says how many are hidden now ("3 hidden, on 2 characters."); with none hidden it says "Nothing is hidden." and the button is disabled. No dialog; after a click a good badge "3 to-dos back" shows beside the button for 4 s.
  • Reset to-dos completely…: opens the dialog with Cancel focused, so Enter or Esc changes nothing. "Reset to-dos", on every character: your own to-dos are removed, every hidden to-do comes back, every count you typed and every amount typed in the Resources window is emptied ("—"); values from the game stay (they are the game's, and come back at each login anyway). The reset hour and the membership stay. Afterwards a good badge "To-dos reset" shows beside the button for 4 s; open to-do and Resources windows show the fresh values at once.
  • Not here: hiding and showing single rows, adding your own and the counts stay in the to-do window; amounts are typed in the Resources window. "+1?" from boss kills (built later, off by default) would get its switch here. No switch to stop filling from the game: typing over a value covers a wrong one, and the next login fixes it.
